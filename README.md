# SkillUp — AI Developer Onboarding Platform

Express + SQLite backend with a single-page HTML frontend, served together on
one port. Multi-user with real authentication.

## Requirements

- **Node.js 22.5+** (uses the built-in `node:sqlite` module — nothing to
  compile). Check with `node -v`.

## Setup

```bash
npm install
cp .env.example .env
```

Then edit `.env`:

```bash
# Required
JWT_SECRET=$(node -e "console.log(require('crypto').randomBytes(48).toString('hex'))")

# Optional — leave blank to run chat in demo mode
AI_API_KEY=your_groq_key_here
```

```bash
npm run seed     # populates shared content: modules, badges, KB articles…
npm start
```

Open **http://localhost:5000** and create an account — the frontend is served
by the backend, so there's no separate dev server and no CORS setup needed.

## What's different from a typical starter

Progress, points, streaks and badges are **per-user**, not global. Two people
can create accounts on the same server and neither sees the other's data —
every route past `/api/auth` requires a bearer token, and every query filters
on the signed-in user's id.

Points, badges and streaks are **server-authoritative**. The client never
tells the server how many points to award; it tells the server what happened
("module 3 completed") and the server decides the consequence, guards against
replay (re-completing an already-done module is a no-op), and reverses the
grant if the action is undone (un-ticking a checklist item gives the points
back).

## Scripts

| Command | What it does |
|---|---|
| `npm start` | Runs the server on `PORT` (default 5000) |
| `npm run dev` | Same, with nodemon auto-restart |
| `npm run seed` | Rewrites the shared content tables (safe to re-run) |

## API

`/api/auth/*` is public. Everything else requires `Authorization: Bearer <token>`.

| Method | Route | Purpose |
|---|---|---|
| POST | `/api/auth/signup` · `/login` | Create account / sign in |
| GET | `/api/auth/me` | Current user |
| GET | `/api/dashboard` | Points, streak, heatmap (derived, not stored) |
| GET | `/api/modules` `?all=1` | Modules, filtered to skill tier unless `all=1` |
| PATCH | `/api/modules/:id/complete` | Mark complete (idempotent, awards points once) |
| GET | `/api/onboarding` | Checklist |
| PATCH | `/api/onboarding/:id/toggle` | Toggle (awards/reverses 20 pts) |
| GET | `/api/assessment/questions` | Assessment questions with weighted options |
| POST | `/api/assessment/submit` | Scores, sets `profile.level`, which gates modules |
| POST | `/api/chat` | AI chat (rate-limited, sends recent history as context) |
| GET · DELETE | `/api/chat/history` | Paginated history / clear it |
| GET | `/api/kb` · `/search?q=` | Knowledge base |
| POST | `/api/kb/:id/view` · `/vote` | View count / helpful vote |
| GET | `/api/notifications` | Per-user feed |
| PATCH | `/api/notifications/:id/read` · `/read-all` | Mark read |
| GET | `/api/leaderboard` · `/badges` | Real users merged with seeded rivals |
| GET | `/api/github-activity` | Live GitHub data if `GITHUB_REPO` is set, else seeded |
| GET | `/api/team` · `/explorer` | Static content |
| GET · PUT | `/api/profile` | Read / update (points and level are not client-writable) |

## AI chat

Uses the Groq API. Free key: <https://console.groq.com/keys>.

```
AI_API_KEY=gsk_your_key_here
AI_MODEL=groq/compound-mini
```

No key set → clearly-labelled demo replies instead of failing. The last 10
messages are sent as context, so follow-up questions work.

## GitHub activity (optional)

```
GITHUB_REPO=owner/name
GITHUB_TOKEN=ghp_optional_for_higher_rate_limit
```

Unset → the feed shows seeded example activity instead.

## Security notes

- Passwords are bcrypt-hashed; sessions are JWTs (7-day expiry).
- `helmet` sets a content security policy; `express-rate-limit` throttles
  login attempts (20/15min) and chat messages (15/min).
- Chat messages are HTML-escaped before markdown formatting, so a message
  containing `<script>` or an `onerror` payload can't execute.
- `JWT_SECRET` must be set via environment variable in production — the
  server refuses to start without one when `NODE_ENV=production`.

## Known gaps

- No password reset flow.
- No refresh tokens — an expired session just requires signing in again.
- SQLite is fine for a single instance; move to Postgres before running
  more than one server process.

## Live-feature notes (v3.1)

- **GitHub Activity** — set `GITHUB_REPO=owner/name` in `.env` (and ideally `GITHUB_TOKEN`, which lifts GitHub's limit from 60 to 5000 req/hr), or type any public repo into the "Connect Repository" box (`GET /api/github-activity?repo=owner/name`). Commits, PRs and issues are fetched independently; a failing section falls back to demo rows for that section only. The page badge shows `● LIVE`, `◐ PARTIAL LIVE` or `DEMO DATA`.
- **Knowledge Base** — searching calls `GET /api/kb/search`, expanding an article calls `POST /api/kb/:id/view`, voting calls `POST /api/kb/:id/vote`, and "Ask a Question" calls `POST /api/kb/ask` (real AI answer saved for the whole team; needs `AI_API_KEY`).
- **JWT** — `JWT_SECRET` must be 32+ random characters. If unset in development a random secret is generated once and saved to `.jwt_secret`; in production the server refuses to start without one.
